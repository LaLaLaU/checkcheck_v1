# 喷码集成两路线决策记录（UI 自动化 A vs RS‑232/SCI 直连 B）

本文档沉淀当前对接 Videojet 1620HR（VJ1000 生态）喷码链路的两条实施路线，便于随时切换或并行推进。所有参数以现场配置为准。

---

## 背景与目标
- 上游：OCR 识别只能得到“图号+架次号”的一部分（例：`ABC.123.D.555.123`）
- 下游：实际喷印需要“功能 + 图号 + 架次号”
- 资产：已有大量以“图号命名”的字符文件（如 `.948`），为逐列位图（16 高 × W 宽，每列 16 位 0/1）。示例文件：`resources/J11B.5324.B.655.971`
- 接口：设备支持 RS232/以太网；现场采用 RS232（9600, 8N1, Parity=None, RTS/CTS）
- 现状：厂家喷码软件已稳定使用并独占 COM 口

目标：在不影响生产的前提下，实现 OCR → 选文件/组装 → 下发喷印 的稳定自动化。

---

## 路线 A：保留厂家软件，用 UI 自动化驱动

### 思路
- 不接触设备协议，由厂家软件负责渲染与发送。
- 我方程序负责：
  1) 解析 OCR，提取【图号】【架次号】；
  2) 索引 `.948`（按文件名=图号，含规范化/模糊匹配）；
  3) 通过 UI 自动化：打开对应 `.948` → 在“架次/批次/Lot/Batch”输入框写入 → 点击“发送/传输信息”；
  4) 读取状态区文本判断成功（如包含“发送完成/ACK/COMx(9600)…已打开”），并记录历史。

### 关键配置（建议外置 `configs/vendor_app.yaml`）
- `exe_path`：厂家软件路径
- `title_re`：主窗口标题正则
- `selectors`：打开文件、架次号编辑框、发送按钮、状态区文本 的 UIA 选择器（含热键回退）
- `.948_dir`：字符文件根目录；索引与纠错映射（编辑距离候选）
- 去抖参数：内容去重与最小更新间隔（200–500ms）
- 校验：允许字符白名单、最大长度、超长截断

### 架构要点
- UIA 优先，热键回退，必要时图像识别兜底；
- 程序不打开串口，避免与厂家软件抢占；
- 弹窗哨兵：端口占用、文件不存在、格式不符、许可提示等；
- 历史入库：`ocr_raw, drawing_no, sortie_no, final_text, sent_ok, ts`。

### 难点与对策
- 控件脆弱：版本/标题/缩放变化 → 多条件选择器 + 外置配置 + 热键回退；冻结软件版本与 Windows 缩放 100%。
- 时序：加载 `.948` 需要时间 → 显式等待 Ready/进度完成，超时与指数退避重试。
- 弹窗阻断：正则规则自动处理，三次失败转人工模式并截图。
- 文件歧义：OCR 与文件名差异 → 规范化 + 编辑距离候选 + 纠错映射表。
- 字符/长度：发送前白名单与截断；全量样本干喷预检。

### 何时选 A
- 已有大量 `.948` 且必须保持现有字形效果；
- 需要“零协议取证、最快上线”。

### 风险
- UI 自动化天然易碎；依赖前台焦点与交互式会话，RDP/屏保影响稳定性；变更需回归测试。

---

## 路线 B：绕过厂家软件，RS‑232/SCI 直连

### 思路
- 程序直接打开串口，按设备协议（SCI/High Speed Remote Data Transfer）写“可变字段”。
- 作业设计为“单字段 `CODE`”，程序把“功能+图号+架次号”拼成一串后写入；由传感器触发喷印。
- `.948` 仅作为离线“数据源”（抽取功能/标准化图号），不直接下发。

### 必要条件
- 获取官方协议/命令集（推荐），或抓厂家软件串口帧还原命令；
- 设备端：
  - 预建作业（示例 `JOB1`）；
  - 字段名：`CODE`（英数字与下划线，长度受限）；
  - Remote Source=RS232；
  - Print ACK ASCII=明确字节（建议 `0x06`）。

### 架构要点
- 串口客户端：9600, 8N1, None, RTS/CTS；后台线程读、队列串行写、超时与重试、掉线自恢；
- ACK/NAK 判定：按“Print ACK ASCII”；
- 去抖：内容不变不发送，最小间隔 200–500ms；
- 可观测性：命令/回包/耗时全链路日志，健康检查脚本；
- `.948` 扫描生成 `{图号 → 功能, 标准图号, 文件路径}` 映射（JSON/SQLite）。

### 难点与对策
- 协议不透明 → 索要 SCI 文档；拿不到则抓包（驱动级工具/虚拟串口分流/硬件分线）；
- 作业与变量绑定 → 规范命名与长度校验，程序侧白名单与截断；
- 生产节拍 → 只在变更时发送，必要时读取 Ready/Busy；
- 可靠性 → RTS/CTS、优质线缆/转接头、超时重试与指数退避；
- 字符集 → ASCII 优先；中文需确认字库；
- 端口独占 → 路线 B 下停用厂家软件串口功能，单进程单通道。

### 变体 B2（保真字形：位图/LOGO）
- 解析 `.948` → 16×W 二值矩阵 → 按 LOGO/位图下载命令写入设备 → 作业引用 LOGO，变量仅写“架次号”。
- 必须拿到 LOGO 下载帧格式（或抓包）。

### 何时选 B
- 追求长期稳定、摆脱 UI 脆弱性；
- 需要与其他系统更紧耦合与可观测。

### 风险
- 前期取证成本（协议/抓包）；
- 作业/字段变更导致配置漂移（需外置配置 + 启动自检）。

---

## 两路线切换与并行策略
- 单一配置开关：`mode: vendor_ui | serial_sci`；
- 共享模块：OCR 解析与规范化、`.948` 索引与纠错映射、去抖与历史记录；
- 切换 Runbook：
  1) 关闭当前模式进程（避免串口冲突）；
  2) 切换配置并启动对应服务；
  3) 健康检查：
     - UI：打开→载入→填值→发送（检查状态文本）；
     - SCI：打开串口→发测试命令→收 ACK；
  4) 空跑 30 分钟并核查日志。

---

## 健康检查与验收
- UI 路线：10 个覆盖样例 `.948` 全流程成功率 ≥ 99%；弹窗规则覆盖 ≥ 95%。
- SCI 路线：ACK 成功率 ≥ 99.9%，单条指令 ≤ 1s 确认；30 分钟干喷无丢喷/错位。

## 附：`.948` 文件理解（结合样例 `resources/J11B.5324.B.655.971`）
- 文件为“逐列位图”文本：每行 16 位（上→下），整文件按列从左→右拼接；
- 末尾大量全 0 列表示右侧留白；
- 首行如 `09X07/16/100/5`：16 为字高；100 多为目标列数/宽度设定（以厂家定义为准）。
